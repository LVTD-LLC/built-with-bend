Choose a MyLSM example before integrating

Start with text if your keys and values are strings, binary access if they are arbitrary bytes, or a snapshot scan if a reader must retain an earlier view while writes continue. These are three different learning tasks, not three database engines.

Source review, November 16, 2026: the upstream 0.6.0.2 release notes describe a native owner crash exposed by Bend 2.0.40 and require rebuilding native binaries with the updated environment. Public APIs and storage formats are unchanged; existing 0.6 databases need no migration. This does not waive migration requirements for older formats.

  1. Text write/read: follow utf8_basic.bend. MyLSM.Utf8 encodes strings as UTF-8 and reports invalid stored text rather than replacing bytes.
  2. Binary keys and values: read bytes_basic.bend. MyLSM.Bytes accepts byte buffers, including bytes outside valid UTF-8; keys use unsigned lexicographic byte order.
  3. Stable reads during updates: inspect snapshot_scan.bend. It reads the old value through a snapshot, closes the cursor and snapshot, then reads the new live value.

The pinned example instructions require Bend 2.0.40 and a fresh, nonexistent MYLSM_DB_PATH for each run. The database remains afterward. Read the durable API’s handle and error rules before adapting an example; a lost response after a dispatched write can leave the outcome unknown, so inspect before retrying.

Built with Bend reviewed these sources, not an installation or runtime execution. The release’s compatibility evidence is for Apple Silicon macOS; it does not establish Linux or GPU compatibility. Formal laws cover pure decisions, not filesystem or host effects. The dated 0.6.0.0 overview above remains an earlier source review, not a recommendation to skip the newer release notes.

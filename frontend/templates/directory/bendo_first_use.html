Try Bendo’s local Bend 2 web server

Start with Bendo’s hello example to explore a Bend 2 web framework before adding a frontend. Bendo is pre-alpha: its maintainer has not published the toolkit to npm, and the API can change. Use the checkout instructions, not the prospective bun create bendo command.

The pinned quick start specifies Bend 2.0.38, Bun 1.4.4 and clang. Follow its versioned compiler download rather than assuming the latest Bend installer matches. After cloning, select the checked source with git checkout a42deb9.

  1. In the Bendo checkout, compile bend examples/hello/main.bend -o hello, then start ./hello.
  2. In a second terminal, run curl http://127.0.0.1:8787/todos/42. Expect Hello from Bendo! You asked for /todos/42. Stop the server when finished.

For a larger starting point, the checkout-only scaffolder offers an API template or a fullstack template with React and a typed client. Those templates are separate from the hello example tested here.

The maintainer’s law coverage distinguishes pure-code proofs from IO; this HTTP smoke check did not verify the documented proofs or full IO behavior.

Trace a real todo request through the typed client

The hello example echoes a path; it does not load a todo. For a stateful API and React client, continue with the checkout’s todo example rather than treating hello as a working todo application.

  1. Follow the pinned todo setup with the same Bend 2.0.38 and Bun 1.4.4 toolchain. Run the API and web app in separate terminals. The API binds to localhost; another device needs forwarding or a proxy, not just a changed browser URL.
  2. Read the example’s client setup: it imports generated route types and response schemas, then creates the client with both. The result contract distinguishes data, HTTP rejection, network failure and invalid responses. Narrow on kind === "data" before reading a todo; types alone do not validate a server response.
  3. Create and edit a todo, then try a blank title with Check in the browser disabled. Expect HTTP 422 from the server, not a successful write. After changing routes or schemas, follow the regeneration instructions before trusting the generated client contract.
